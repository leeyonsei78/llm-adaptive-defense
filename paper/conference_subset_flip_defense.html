소형 로컬 LLM의 자율 공격 성공과 상반된 방어 프로파일:
SQL 인젝션과 API 업무로직 공격의 비교

Autonomous Attacks by Small Local LLMs and Their Opposite Defense Profiles: SQL Injection vs. API Business-Logic Attacks

국문초록

LLM을 두뇌로 삼는 자율 공격 에이전트가 현실 위협으로 부상하고 있다. 그러나 개방형 외부 하네스(Cochise·AutoPenBench·PentAGI)에서 소형 로컬 모델은 실제 공격 트래픽을 대량 생성하면서도 인증 우회·권한 상승에는 단 한 번도 성공하지 못했다. 본 연구는 이 실패가 모델의 근본적 무능인지, 하네스의 과도한 개방성·실행 불안정 탓인지를 분리하기 위해, 행동 공간을 제약하되 LLM이 여전히 모든 행동과 페이로드를 스스로 작성하는 "제약된 자율" 하네스를 설계하였다. 동일한 소형 로컬 모델(llama3.1:8b)로 두 가지 구조적으로 다른 공격을 측정한 결과, 자율 SQL 인젝션은 73%(11/15), API 업무로직 공격(BOLA·권한 상승·BFLA·업무플로우 남용 등 여러 클래스)은 각 10/10으로 성공했으며(모두 표적측 ground truth로 검증, 전부 로컬·격리·무비용), 이는 "소형 모델은 자율 공격을 못 한다"는 인상이 하네스·실행의 문제였음을 보인다. 더 중요하게, 두 공격의 방어 프로파일이 정반대였다 — 시그니처가 있는 SQLi는 시그니처 규칙이 탐지하고 소형 LLM이 놓쳤으며, 시그니처가 없는 업무로직 공격은 시그니처 규칙이 놓치고 인가 맥락을 쓰는 탐지(맥락 규칙·LLM)가 잡았다(정상 세션은 모두 오탐 0). 따라서 공격의 정의가 방어기 선택을 가르며, 어느 한쪽도 단독으로 충분하지 않아 규칙+LLM 병행 방어가 필요하다.

주제어: 자율 공격 에이전트, 대형 언어 모델, SQL 인젝션, API 보안, BOLA, 업무로직 공격, LLM 방어, 침입 탐지

Abstract

Autonomous attack agents driven by LLMs are an emerging real-world threat, yet in open external harnesses (Cochise, AutoPenBench, PentAGI) small local models generate heavy attack traffic but never complete authentication bypass or privilege escalation. To separate whether this failure stems from model incapacity or from harness over-openness and execution instability, we design a constrained-autonomy harness in which the LLM still chooses every action and writes every payload itself, but within a defined action space with stabilized execution. With one small local model (llama3.1:8b), autonomous SQL injection succeeds 73% (11/15) and API business-logic attacks (BOLA + privilege escalation, and separately BFLA + business-flow abuse) each succeed 10/10 (all verified by target-side ground truth, all local and free). Crucially, the two attacks have opposite defense profiles: signature-bearing SQLi is caught by a signature rule but missed by the small LLM, whereas the signature-free business-logic attack is missed by the signature rule but caught by authorization-context detection (context rule and LLM), with zero false positives on benign sessions. Thus the definition of the attack determines the choice of detector, and a rule+LLM ensemble is required.

Keywords: autonomous attack agents, large language models, SQL injection, API security, BOLA, business-logic attacks, LLM defense, intrusion detection

1. 서론

LLM을 의사결정 두뇌로 삼아 정찰·침투·권한 상승을 스스로 반복하는 자율 공격 에이전트가 빠르게 발전하고 있다[1,2]. 방어 측에서 이 위협을 평가하려면, 실제 공격 하네스를 격리 환경에서 구동해 "무엇이 실제로 성공하는가"를 표적측 사실(ground truth)로 확인하는 것이 중요하다. 선행 작업에서 우리는 세 가지 공개 자율 공격 하네스(Cochise·AutoPenBench·PentAGI)를 격리된 가상 환경에서 로컬 소형 모델로 구동하였는데, 에이전트는 nmap·sqlmap 등 실제 공격 트래픽을 대량 생성했음에도 인증 우회·크라운주얼 획득에는 한 번도 성공하지 못하고, 때로는 성공을 스스로 과대보고(환각)하였다 — 표적 로그가 이를 반증한다[8].

이 결과만 보면 "소형 로컬 모델은 자율 공격 능력이 없다"고 결론짓기 쉽다. 그러나 그 실패가 (a) 모델의 근본적 무능인지, (b) 개방형 하네스의 다단계 계획 부담·불안정한 도구 실행 탓인지는 구분되지 않았다. 본 연구는 스캐폴딩 스펙트럼의 반대쪽을 측정하여 이 둘을 분리한다 — LLM이 여전히 모든 행동과 공격 페이로드를 스스로 작성하되, 행동 공간을 실제 HTTP 원시 동작으로 제약하고 실행을 안정화한 "제약된 자율" 하네스를 설계한다.

연구 질문. RQ1. 행동 공간을 제약하면 동일한 소형 로컬 모델이 자율적으로(스스로 페이로드 작성) 공격에 성공하는가? RQ2. 이 성공이 특정 공격 클래스(시그니처가 있는 SQLi)에 국한되는가, 아니면 시그니처가 없는 API 업무로직 공격에서도 재현되는가? RQ3. 실제로 성공한 자율 공격을 어떤 방어기(시그니처 규칙·맥락 규칙·LLM)가 탐지하며, 공격 종류에 따라 그 결과가 달라지는가?

기여.

(C1) 개방형 하네스에서 0회 성공하던 소형 로컬 모델(llama3.1:8b)이 제약된 자율 하네스에서는 자율 SQL 인젝션 73%, 자율 API 업무로직 공격(BOLA+권한 상승) 10/10으로 성공함을 표적측 ground truth로 보인다 — 소형 모델의 자율 공격 실패는 근본 무능이 아니라 하네스·실행의 문제였다.
(C2) 성공한 두 자율 공격의 방어 프로파일이 정반대임을 측정한다 — 시그니처 유무가 어떤 탐지기가 작동하는지를 가른다.
(C3) 이로부터 "공격이 시그니처로 정의되면 규칙, 인가 맥락으로 정의되면 LLM"이라는 탐지기 선택 원칙을 실제로 성공한 자율 AI 공격 두 종에 대해 실증하고, 규칙+LLM 병행의 필요성을 제시한다.

2. 관련 연구

자율 침투 에이전트. PentestGPT[2]는 LLM 기반 침투시험 자동화의 한계를 벤치마크로 평가해 맥락 상실과 서브태스크 성공률을 보고하였고, ZERO-APT[1]는 지능형 방어 하에서도 LLM 공격 에이전트가 높은 성공률에 이를 수 있음을 보였다. 이들은 주로 강한(호스티드) 모델을 전제하거나 공격 성공 자체에 초점을 두며, 소형 로컬 모델의 실패 원인 분리와 성공한 공격에 대한 방어는 다루지 않는다.

API 보안과 업무로직 공격. OWASP API Security Top 10(2023)[3]은 BOLA(Broken Object Level Authorization)를 API 1위 위험으로 유지한다. Kaur[4]는 100건 이상의 버그바운티 공개로 BOLA를 분류하고 기존 문헌이 대부분 개념적임을 지적하며, Wu 등[5]은 자원 ID 데이터 흐름을 추적하는 Bolaz를 제안한다. 산업 보고서[6]는 금융을 API 공격 1위 표적으로, BOLA·파라미터 조작을 "시그니처 도구와 거친 rate limit이 놓치는" 벡터로 지목한다 — 본 연구가 그 공백을 로컬 LLM 방어 축에서 실측한다.

LLM의 취약성과 신뢰성. 프롬프트 인젝션은 LLM 통합 애플리케이션의 구조적 취약점이며[7], LLM의 환각·자기보고 신뢰성 문제[8]는 "성공했다"는 자기보고를 표적측 사실로 반증해야 함을 시사한다. 국내에서도 SQL 질의 구조 분석 기반 SQLi 탐지[9], LLM·프롬프트 엔지니어링을 이용한 다단계 공격 시나리오 탐지[10], LLM 기반 침입탐지[11]가 보고되었으나, 성공한 자율 공격 두 종에 대한 탐지기별 상반 결과를 교차 측정한 연구는 드물다.

3. 방법

3.1 제약된 자율 하네스

에이전트는 LLM이 다음 행동을 스스로 선택하고 그 값(공격 페이로드·조회 대상·설정 필드)을 직접 작성하지만, 행동 공간은 실제 HTTP 원시 동작(정찰 / 로그인 / 자원 조회 / 프로필 수정)으로 제약하고 실행을 안정화한다(추상화된 ReAct와 개방형 하네스의 중간; "정의된 행동 공간 내 자율"). LLM에는 정확한 익스플로잇을 주지 않고 취약점 클래스 수준의 정찰 사실만 제공한다(예: SQLi는 "로그인이 문자열 결합으로 구성됨", 업무로직은 "소유권 미검증·필드 allowlist 부재"). 두뇌는 로컬 Ollama의 llama3.1:8b이다.

3.2 표적과 ground truth

두 합성 표적을 사용한다. (1) SQLi 표적: 문자열 결합 쿼리로 인증하는 취약 로그인과 보호 자원(크라운주얼)을 갖는 합성 웹 서버. (2) 금융 API 표적: 계정·잔액·프로필 API에 소유권 미검증(BOLA)과 프로필 대량할당(mass assignment) 취약점을 심은 합성 API. 두 표적 모두 모든 요청과 결과를 로그로 남겨, 공격 성공 여부를 모델의 자기보고가 아니라 표적측 사실 (login_ok ∧ crown_jewel, bola_violation ∧ privilege_escalation)로 판정한다.

3.3 방어기

성공한 공격 세션에 세 가지 탐지기를 겨눈다. 시그니처 규칙(페이로드 패턴 정규식), 맥락 규칙(요청의 소유권·역할 맥락을 관측값으로 계산해 비소유 객체 접근 등을 판정), LLM(llama3.1:8b, 세션 1회 판정, temperature 0). 정상 세션 1건을 대조로 둔다.

3.4 환경과 윤리

모든 공격은 저자가 만든 합성 표적에 대해 로컬 루프백·격리 환경에서만 수행하였고, 외부 서비스·실존 시스템·개인정보를 대상으로 하지 않는다. 모든 추론은 로컬 Ollama로 수행하여 무비용이며, 연구 목적은 방어 설계 개선으로 바로 악용 가능한 완성형 공격 페이로드 모음은 배포하지 않는다.

플립이 공격 클래스를 넘어 일반화한다. 동일 소형 모델이 시그니처가 전혀 없는 업무로직 공격에서도 10/10 완전 장악에 성공했다. 그러나 방어 결과는 SQLi와 정반대였다 — 시그니처 규칙이 놓치고, 맥락 규칙·LLM이 잡았다.

동일한 자율성으로 또 다른 두 signature-free 클래스 — BFLA(관리자 전용 함수를 저권한 사용자가 호출)와 업무플로우 남용(음수 이체) — 에서도 재현하였다. 소형 모델은 두 공격 모두 10/10 완전 장악에 성공했고(표적 GT), 방어 프로파일도 동일했다 — 시그니처 규칙은 놓치고 맥락 규칙·LLM이 잡았다(정상 오탐 0). 다만 LLM은 이체 금액과 호출자 역할을 관측값으로 받았을 때 비로소 공격으로 판정했다 — 업무로직 탐지에는 인가 맥락을 LLM에 반드시 제공해야 함을 보인다(정보 대등성).

표 5. 성공한 자율 공격 4종의 방어 프로파일 대조 — 공격 정의가 작동하는 방어기를 가른다(정상 세션은 전 행 오탐 0).

4.4 탐지 이분법 (그림)

공격이 페이로드 시그니처로 정의
예: SQL 인젝션 (' OR 1=1 --)
시그니처 규칙 → ✓ 저비용·결정적 탐지
소형 LLM → ✗ 놓칠 수 있음
공격이 인가 맥락으로 정의
예: BOLA · BFLA · 업무플로우 남용
시그니처 규칙 → ✗ 무력
맥락 규칙·LLM → ✓ 탐지 (인가 맥락 입력 필요)
↓ 어느 쪽도 단독으로 두 유형을 모두 막지 못함 → 규칙 + LLM 앙상블 필요
그림 1. 탐지 이분법 — 공격이 무엇으로 "정의"되느냐(페이로드 시그니처 vs 인가 맥락)가 어떤 방어기가 작동하는지를 가른다.

5. 논의

두 결과를 합치면 하나의 명제가 선다 — 공격의 정의가 방어기 선택을 가른다. 공격이 페이로드 시그니처로 정의되면(SQLi) 시그니처 규칙이 저비용·결정적으로 탐지하고 소형 LLM은 오히려 놓치며, 공격이 인가 맥락으로 정의되면 (BOLA·BFLA·업무플로우 남용) 시그니처 규칙은 무력하고 인가 맥락을 쓰는 탐지(맥락 규칙·LLM)만 작동한다. 어느 한쪽도 두 유형을 모두 단독으로 막지 못하므로, 실무 방어는 규칙+LLM 병행(앙상블)이 필요하다. 이는 "AI 방어가 규칙보다 일반적으로 우월하다"는 주장이 아니라, 공격 종류에 조건부라는 점을 성공한 자율 공격 네 종으로 실증한 것이다.

한계. (1) 행동 공간을 제약한 "정의된 자율"이며 완전 개방형 자율성은 아니다(스펙트럼상 중간). (2) 단일 합성 표적·소형 모델 1종이고, 공격 성공은 확률적이다(SQLi ~73%). (3) 방어 측정은 짧은 세션(세션당 1회 판정)으로, 더 큰 규모·독립 holdout·교차 모델 검증이 필요하다. 이들은 본 발표의 확장판(전체 논문)에서 능력 사다리·교차 모델·강한 모델(GPT-5)·외부 공개 벤치마크(CSIC-2010)로 보완된다.

6. 결론

개방형 하네스에서 0회 성공하던 소형 로컬 모델이, 행동 공간을 제약한 자율 하네스에서는 자율 SQL 인젝션 73%, API 업무로직 공격 10/10으로 성공했다(전부 표적측 ground truth 검증, 로컬·격리·무비용). 더 중요하게, 성공한 두 공격의 방어 프로파일이 정반대였다 — 시그니처가 있으면 규칙이, 인가 맥락으로 정의되면 LLM·맥락 규칙이 잡는다. 따라서 자율 AI 공격 시대의 방어 설계는 공격의 정의에 따라 탐지기를 선택하고 규칙과 LLM을 병행해야 한다.
