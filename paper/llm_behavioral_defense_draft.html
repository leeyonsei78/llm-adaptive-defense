Abstract

본 연구는 AI 적응형 공격에 대한 AI(LLM) 방어의 가능성과 효과, 그리고 설계 원칙을 로컬·합성 환경에서 실측한다. Windows 로컬 환경(Ollama + Qwen 2.5-Coder 14B / DeepSeek-Coder-v2 16B)에서 세 가지 축으로 실험하였다: (1) SQL 인증 공격·방어의 정책 적용 시점(동기/비동기), (2) 적응형 공격자가 피드백을 보고 로그인 속성을 바꾸는 계정 탈취(ATO) 능력 사다리, (3) 공격자·방어자를 서로 다른 모델 계열로 교차한 다중 모델 비교.

SQL 재생 실험(5조건·3반복, 150 요청)에서 공격 성공은 방어 없음 12/12, 고정 규칙 3/12, 항상 안전한 구현 0/12, 동기 AI 0/12, 비동기 AI 3/12였고, 도착률을 고정한 개방형 스윕에서 비동기 방어의 패치 전 도착 요청 수는 floor(추론시간×RPS)+1 모델과 거의 일치했다. 계정 탈취 능력 사다리(216캠페인, 동일 Qwen 계열)에서는 비밀번호만 아는 공격자(L1)는 거의 모든 방어가 막았으나, 탈취된 기기·세션을 가진 공격자(L3)는 여섯 방어 중 다섯이 80% 이상 뚫렸다. LLM 방어는 규칙보다 정상 사용자 마찰을 크게 줄였으나(마찰 합 11~12 대 42~58) L2 단계 공격을 더 많이 통과시키는 트레이드오프를 보였다. 교차 모델 실험(DeepSeek↔Qwen, 셀당 n=12)에서는 방어자 모델에 따라 효과가 결정되어, 가장 어려운 L3 단계를 막은 유일한 설정은 DeepSeek 방어자+llm_escalate(0/12)였고 Qwen 방어자는 같은 방식으로도 뚫렸다(12/12). 단 DeepSeek 방어는 2~9배 느렸고, 동일 설정 2회 실행 중 3셀이 불일치해 로컬 추론의 비결정성도 확인되었다.

나아가 격리된(루프백 전용, 합성) 취약 웹 표적에 실제 HTTP 트래픽을 보내는 고정 파이프라인 공격 에이전트 (정찰→열거→SQLi→익스플로잇)를 돌려, 방어자의 규칙 탐지와 LLM 탐지를 실트래픽에서 비교하였다. 그 결과 AI 탐지가 만능이 아님을 확인하였다 — 시끄러운 공격은 둘 다 100% 잡았고, 명확한 SQLi 시그니처가 있는 은밀한 공격에서는 오히려 규칙이 LLM을 앞섰으며(12/12 대 1/12), 탈취된 유효 자격증명 세션은 규칙도 LLM도 전혀 탐지하지 못해(0/12) 사다리 L3의 구조적 한계가 실트래픽에서도 재현되었다. 더 자율적인 에이전트(Cochise)와 networkx 듀얼 그래프 비교에 더해, 외부 자율 하네스 Cochise를 격리된 VirtualBox VM(내부 Docker)에서 실제로 구동하였다(§6.16) — 로컬 소형 모델이 Ollama 네이티브 tool-calling을 안정적으로 수행하지 못한다는 1차 소견을 측정하였다. 또한 tool-calling 호환 모델(llama3.1:8b)로 20분 실구동한 결과, 에이전트는 실제 공격 트래픽(sqlmap 등 332건)을 대량 생성했으나 인증 우회·크라운주얼 획득에는 실패하고 성공을 자기보고(환각)해(표적 로그 login_ok=0·crown_jewel=0이 반증), 소형 로컬 모델 티어의 한계와 표적측 그라운드 트루스 검증의 중요성을 보였다. 두 번째 외부 하네스 AutoPenBench도 같은 격리 VM에서 로컬로 구동해 공격자 실패를 재현했으며, 특히 약한 LLM 평가자가 성공을 과대보고(실패를 성공으로 잘못 판정)(마일스톤 거짓양성 command 86%·stage 80%)함을 결정적 그라운드 트루스로 확인하여 '자기보고를 믿지 말라'는 명제를 평가자에게로 확장하였다(§6.16b). 나아가 최근 금융권의 지배적 위협인 API 업무로직 공격(BOLA·mass assignment·BFLA·비즈니스플로우 남용·크리덴셜 스터핑)을 합성 금융 API에서 판단하게 한 결과, 페이로드 시그니처가 없어 시그니처 규칙은 전부 실패하고 인가 맥락을 쓰는 탐지(맥락 규칙·LLM)만 유효했다(§6.17). 탐지기를 보지 못한 독립 작성자의 blind holdout에서 손수 만든 규칙은 과적합으로 하락(맥락 12/12→13/18)한 반면 LLM(맥락)은 17/18로 가장 잘 일반화해 'AI의 일반화 가치'가 독립 데이터에서 확인됐다(§6.19). 단 그 우위는 모델 의존적(deepseek-coder-v2는 규칙보다 낮음)이고, 맥락이 없으면 LLM은 정상 접근을 오탐했다(§6.18) — 정밀도 비용 때문에 규칙+LLM 앙상블이 필요하다. 입력·표적·탐지기를 개발자가 작성한 데 따른 순환성 우려는 ATO 탐지기에 한해 규칙을 보지 못한 별도 에이전트가 작성한 독립 holdout으로 재검증하여 완화하였고(§6.13, 정확도 유지·주입 취약성 재확인; 저자가 AI 에이전트라는 한계 잔존), 실트래픽 표적의 독립 재작성과 능력 사다리의 동일 모델 계열 한계는 남는다. 따라서 본 연구는 AI 방어의 일반적 우월성을 주장하지 않고, "어떤 모델이, 어떤 공격 난이도에, 어떤 비용으로 작동하는가"라는 조건부 결론을 제시한다.

1. 서론 (Introduction)

인공지능 기술의 발전은 사이버 보안 분야에 양면적 영향을 미치고 있다. 공격자들이 LLM을 활용하여 고도화된 자동화 공격을 수행하는 동시에, 방어 측도 LLM을 활용한 지능형 탐지·대응 시스템 구축을 시도한다. 특히 공격 감지 후 패치 적용까지의 시간적 노출(policy timing gap)은 동기 vs. 비동기 분석 방식에서 보안 결과에 직접적 차이를 만들어낸다.[1]

기존 LLM 기반 IDS 연구[3,5,6]는 주로 탐지 정확도에 집중하였으나, 실제 방어 시스템에서 LLM 추론 지연·모델 선택·공격 난이도가 보안 결과에 미치는 영향은 충분히 탐구되지 않았다. 본 연구는 이 공백을 채우기 위해, 적응형 AI 공격에 대해 LLM 방어가 가능한지·얼마나 효과적인지·어떤 설계 원칙이 유효한지를 로컬·합성 환경에서 조건별로 실측한다. 실험은 SQL 인증(정책 적용 시점), 계정 탈취 능력 사다리, 다중 모델 교차의 세 축으로 구성되며, 여기에 기만(shadow) 방어 민감도(§6.10), 격리 VirtualBox VM에서의 외부 자율 공격 하네스 실구동(Cochise §6.16, AutoPenBench §6.16b), 그리고 최근 금융권의 API 업무로직 공격 판단(규칙 vs LLM, 제3자 blind 독립 holdout·교차 모델 포함; §6.17–6.19)을 더하였다.

본 논문의 연구 질문(RQ)

RQ1 (가능성): LLM 방어는 적응형 AI 공격을 실시간으로 판단·차단할 수 있는가? 어느 공격 난이도까지 막는가?

RQ2 (효과·비용): 그 효과는 공격 능력 단계·방어 모델·적용 시점(동기/비동기)·정상 사용자 마찰에 따라 어떻게 달라지는가?

RQ3 (설계·대비): 규칙·LLM·기만(deception) 중 어떤 방어 설계가 유효하며, 자율 공격 에이전트 시대의 사고 대비는 어떻게 해야 하는가?

2. 관련 연구 (Related Work)

2.1 전통적 IDS

Snort, Suricata 등 시그니처 기반 IDS는 알려진 공격 패턴에 대해 높은 탐지율을 보이나, 패턴 변형 공격과 제로데이 위협에 취약하다. 본 연구의 고정 규칙 조건은 이러한 한계를 실험적으로 재현한다 — 아포스트로피 계정(O'Reilly)을 정상 차단하고, SQL 주석 변형 공격은 통과시키는 반례를 의도적으로 포함하였다.

2.2 ML/LLM 기반 IDS

SHIELD[5]는 LLM을 호스트 기반 침입 탐지에 적용한 최초의 체계적 프레임워크로, 5개 대표 HIDS 대비 우수한 성능을 달성하였다. EADL-IDS[6]는 RAG를 활용한 비지도 학습 기반 LLM-IDS를 제안하였다. 그러나 두 연구 모두 LLM 추론 지연이 방어 타이밍에 미치는 영향은 분석하지 않았으며, 본 연구는 이 측면에 초점을 맞춘다.

2.3 적응형 공격 연구

ZERO-APT[2]는 LLM 기반 공격 에이전트가 지능형 방어 하에서도 79%의 공격 성공률을 달성함을 보였다. AMDS[7]는 공격 유형별 탐지 전략을 동적으로 조정하여 94.4% 정확도를 달성하였다. 본 연구는 이보다 작은 규모이지만, 실제 모델을 이용한 공격 생성과 방어 분석을 동일 시스템에서 실행하여 타이밍 효과를 직접 측정한다는 점에서 차별화된다.

4.3 정책 엔진 (Qwen · DeepSeek)

AI 조건에서 Qwen 2.5-Coder 14B(기본)는 현재 HTTP 요청과 이전 이력을 분석하여 monitor(감시 유지) 또는 parameterize(파라미터화 쿼리로 패치) 중 하나를 선택한다. 새로운 방어 코드를 생성하지 않으며, 패치는 한 번 적용되면 이후 요청에 영구 유지된다.

이후 실험은 모델 의존성을 분리하기 위해 두 번째 계열인 DeepSeek-Coder-v2 16B를 도입한다 — 6.11절(교차 모델)에서 공격자·방어자를 Qwen↔DeepSeek로 교차하고, 보조로 deepseek-r1:8b도 설치되어 있다. 계정 탈취(6.6–6.9)·독립 holdout(6.13–6.14)·에이전트(6.15)의 LLM 호출은 기본 Qwen을 쓰되, L3 단계를 유일하게 막은 설정이 DeepSeek 방어자였다는 점(6.11)에서 모델 선택이 결과를 좌우하므로 두 계열을 나란히 보고한다. 두 모델 모두 동일한 로컬 Ollama·temperature 0·고정 seed 설정을 공유한다.

• 비율 x/N(예: 9/12): N번 중 x번 발생. "공격 성공/시도"면 낮을수록 방어가 좋음, "정상 유지/요청"이면 높을수록 좋음.

핵심 발견: L3_device(탈취 세션 보유)에서는 여섯 방어 중 다섯이 80% 이상 뚫렸다. rules·llm_escalate(0.92), rules2(0.83)는 통계적으로 구별되지 않는다(95% CI가 크게 겹침). 이 단계에서는 로그인 시점의 속성만으로 공격자와 정상 사용자를 구분할 정보 자체가 없다는 구조적 한계로 해석한다 — 방어 설계의 결함이 아니라 입력 정보의 한계다.
LLM 방어가 규칙보다 항상 낫지 않다: L2_informed에서 llm_sync·llm_history는 100% 뚫렸으나 rules·rules2는 0%였다. 두 LLM 방어 모두 국내 접속·평소 시간대·기기 미보유 상태를 challenge 이상으로 올리지 못했다. 설계상 규칙만 강화하는 llm_escalate는 L2_informed에서 규칙과 동일(0%)했고, 이는 "LLM이 탐지를 추가하지 못하면 규칙 수준으로 수렴한다"는 것을 보여준다.

반면 정상 사용자 마찰에서는 llm_sync·llm_history가 가장 낮았다(마찰 합 11~12, lock 0건). rules2는 정상 lock이 10건으로 가장 공격적이었다. 즉 이 실험의 LLM 방어는 정상 사용자를 더 적게 막는 대신, L2 단계 공격을 더 많이 통과시키는 트레이드오프를 보였다.
한계: (1) 공격자·방어자가 같은 모델 계열(Qwen)이라 다른 가족 모델(DeepSeek-Coder 등)에서 같은 패턴이 재현되는지는 별도 실험(6.11절, 완료)에서 교차 검증하였다 — L3 방어 효과가 방어자 모델에 따라 크게 갈렸다. (2) 소진(exhausted, L1_cred의 llm_sync)은 lock과 달리 "막았다"로 집계했으나 계정을 잠그지 못한 상태이며, 공격자가 8회를 넘겨 재시도하면 결과가 달라질 수 있다. (3) challenge를 공격자가 항상 통과하지 못한다는 가정(FRICTION 테이블)은 단순화다. (4) 원 표 14는 방어자 temperature 0(결정적)이라 12반복이 완전히 독립적인 표본은 아니었다 — 아래 "강건성 검증"에서 방어자를 temperature 0.7·독립 seed로 다시 돌려 핵심 발견이 통계적으로 유지됨을 확인하였다.

6.10 기만(Shadow) 방어 민감도 분석

6.9절에서 L3_device 단계는 모든 방어가 거의 뚫렸다. arXiv 2611.07611("Gingerbread House")의 구조를 참고하여, 로그인을 허용한 뒤 계정 화면에 미끼(가짜 보안 질문·가짜 API 키 메뉴·가짜 복구 연락처)를 두고, 공격자가 미끼를 건드리면 가짜 데이터로 채워진 그림자 계정으로 전환하는 방어를 분석적으로 설계하였다. LLM 호출은 없으며, 미끼 접촉 확률은 실측값이 아니라 가정값(swept assumption)이다. 판단(언제 로그인을 허용하는가)은 rules2를 그대로 쓰고, 달라지는 것은 로그인 이후뿐이다. 따라서 이 절은 lock 방어와 shadow 방어의 차이만 분리해서 보여준다.

정상 사용자 비용도 같은 모델로 계산하였다. 정상 개발 사례 20건 중 rules2가 허용한 로그인 14건을 기준으로, 정상 사용자가 행동마다 1%의 확률로 미끼를 건드린다고 가정하면 평균 0.82건이 그림자에 갇히고, 5%로 가정하면 평균 3.71건이 갇힌다(갇힘 비용은 lock과 동일한 가중치 5로 가정).

이 결과는 효과 측정이 아니라 가정 위에서의 계산이다. 미끼 접촉 확률이 공격자·정상 사용자 모두에게 실제로 얼마인지는 이 시뮬레이션에서 알 수 없다. 현재 공격자는 로그인 시도 속성만 고르는 선택기이며, 로그인 후 행동(미끼를 건드릴지 판단하는 행동)을 하지 않기 때문이다. 또한 공격자가 가짜 데이터를 진짜로 믿고 공격을 끝내는지(기만의 성공)도 이 모델로는 측정할 수 없다. 실제 값은 향후 자율 에이전트 실험(7.4절 (6))에서 측정해야 하며, 이 절의 수치는 그 실험이 어떤 범위의 결과를 낳을 수 있는지 보이는 사전 민감도 분석으로만 읽어야 한다.
업데이트(6.12절): 이후 실트래픽 에이전트 실험에서 미끼 접촉률을 실제로 측정하였다 — 무차별 열거형 고정 파이프라인 공격자의 경우 p_touch ≈ 0.30으로, 위 민감도 표의 0.3 행(그림자 유도율 0.74)에 해당한다. 다만 이는 디코이를 가리지 않고 모두 긁는 공격자의 값이며, 디코이를 회피하는 더 영리한 에이전트는 더 낮을 것으로 예상된다. 따라서 위 가정값 범위는 실측 1점으로 뒷받침되었으나, 여전히 단일 공격자 유형의 값이다.

6.12 실험 I: 실트래픽 탐지 — 규칙 vs LLM (에이전트 공격)

지금까지의 공격자는 로그인 입력을 고르는 "속성 선택기"였다. 이 실험에서는 격리된(루프백 전용, 합성) 취약 웹 표적에 대해 실제 HTTP 트래픽을 보내는 고정 파이프라인 공격 에이전트(정찰→엔드포인트 열거→ SQLi 탐침→익스플로잇→보고)를 돌리고, 방어자가 그 요청 로그를 관측해 공격 세션을 탐지하도록 하였다. 공격 코드는 모든 요청 호스트를 루프백으로 강제하는 allowlist를 코드로 내장해 외부로 트래픽을 보낼 수 없다. 세션을 4종(정상 로그인 / 시끄러운 공격 / 은밀한 공격 / 탈취 자격증명)으로 나누고, 규칙 탐지기 (미끼 경로·SQLi 시그니처·404 열거·허니토큰의 단일 신호 확정)와 LLM 탐지기(동일 로컬 모델이 세션 로그 전체를 1회 판정)를 비교하였다. 규칙 n=12/유형, LLM n=6/유형(비용 상한), Wilson 95% CI.

표 18 읽는 법. 행은 네 종류의 세션이고, 규칙 탐지·LLM 탐지 칸은 "탐지한 세션/전체 세션"이다. 공격 세션 행(시끄러운·은밀한·탈취)은 높을수록 좋고(공격을 잘 잡음), 정상 로그인 행은 0이어야 좋다(오탐 없음). 규칙 탐지 지연은 공격의 몇 번째 요청에서 첫 신호가 떴는지로 작을수록 빨리 탐지(노출 구간이 짧음)다. 핵심은 한 가지 승자가 없다는 것: 시끄러운 공격은 둘 다 100%(이땐 더 싼 규칙으로 충분), 은밀한 공격은 규칙 12/12 > LLM 1/6으로 규칙이 LLM을 이기고(명확한 SQLi 시그니처엔 결정적 규칙이 안정적), 탈취 자격증명은 둘 다 0(요청 로그가 정상 로그인과 똑같아 구조적으로 구분 불가 — §6.9 L3의 실트래픽 재현). 요지: "AI 탐지가 항상 낫다"는 통념과 반대로, 공격이 시그니처로 또렷하면 규칙이, 자격증명이 유효하면 그 무엇도 로그인 시점만으론 못 잡는다.
핵심 발견: AI 탐지는 만능이 아니며, 어려운 케이스는 규칙·AI 모두 어렵다. (1) 정상 세션에서 둘 다 오탐 0 (규칙 CI [0, 0.24], LLM CI [0, 0.39]). (2) 시끄러운 공격은 둘 다 100% 탐지(규칙 CI [0.76, 1.00]) — 이땐 더 싼 규칙으로 충분. (3) 은밀한 공격에서는 오히려 규칙이 LLM을 앞섰다(규칙 12/12 vs LLM 1/12). SQLi 시그니처가 프롬프트에 명시되어 있었는데도 소형 로컬 LLM은 대부분 "정상"으로 오판했다 — 명확한 신호에는 결정적 규칙이 더 싸고 안정적이다. (4) 탈취 자격증명(유효 크리덴셜) 세션은 규칙도 LLM도 전혀 탐지하지 못했다(둘 다 0/12·0/6). 요청 로그가 정상 로그인과 동일하기 때문으로, 6.9절의 L3 구조적 한계가 실트래픽에서도 그대로 재현되었다.
한계: (1) LLM 탐지기는 소형 로컬 모델·80토큰·세션 1회 판정 설정이므로, "LLM이 은밀한 공격에 약하다"는 결론은 LLM 일반이 아니라 이 구성에 대한 것이다. 더 큰 모델·다단계 판정은 다를 수 있다. (2) 표적·공격자·탐지기를 모두 저자가 작성해 내적 타당성(순환성) 우려가 크다 — ATO 탐지기에 대해서는 6.13절에서 규칙 비공개 독립 holdout으로 재검증하여 완화하였다(일반화 성립); 실트래픽 표적 자체의 독립 재작성은 미수행. (3) 합성 표적 1개, 규칙 n=12·LLM n=6/유형으로 소규모. (4) 은밀한 공격도 따옴표 기반 SQLi라 규칙이 쉽게 잡았고, 인코딩·주석 변형 등 시그니처 회피는 미평가. (5) 탈취 자격증명은 설계상 정상과 동일하므로 "탐지 불가"는 부분적으로 정의적 결과다 — 로그인 시점 단일 세션의 한계를 보여주는 것이지 행위 이력·디바이스 핑거프린트까지 포함한 탐지의 한계는 아니다.

6.13 실험 J: 독립(규칙 비공개) holdout 재검증 — 순환성 완화

6.12절과 7.3절이 지적한 가장 큰 내적 타당성 위협은 순환성이다 — 표적·공격 사례·탐지 규칙을 모두 같은 저자가 작성하여, 탐지기가 잘 맞는 것이 일부 자기충족일 수 있다. 이를 완화하기 위해, 탐지 규칙 (rules/rules2)과 기존 개발 사례를 전혀 보지 못한 별도의 에이전트에게 문제 정의·이벤트 스키마·라벨 정의만 주고 계정 탈취 holdout 사례를 blind로 작성하게 하였다. 이 에이전트는 작업 중 어떤 파일도 열지 않았고(도구 호출 0회) 오직 사양만으로 23개 사례(정상 12, 공격 11, 프롬프트 주입 3 포함)를 생성하였으며, 라벨·정답 조치 집합을 수정 없이 그대로 적재하였다(저자 원본 JSON·작성 프롬프트를 provenance로 보존). 그 뒤 동일한 per-event·무상태 채점(각 이벤트의 조치가 정답 집합에 속하는가)으로 개발 사례(30건·53이벤트)와 holdout(23건)을 rules·rules2· LLM(qwen2.5-coder:14b) 세 탐지기에 대해 나란히 비교하였다. 두 세트를 같은 척도로 다시 채점했으므로, 아래 개발 사례 수치는 6.6절의 서사(사례 단위 탈취 집계)와 직접 비교되지 않는다.

(2) 무상태 채점의 한계: 불가능 이동 탈취(2이벤트)의 첫 이벤트(정상처럼 보이는 홈 로그인)는 세 탐지기가 모두 allow, 둘째(불가능 이동)는 모두 차단했다 — 다중 이벤트 탈취의 첫 신호는 상태를 추적하는 탐지기가 필요함을 시사한다.
독립성의 한계(정직한 고지): holdout 저자는 인간 제3자가 아니라 별도 AI 에이전트다. 따라서 이는 규칙 비공개 + 별도 컨텍스트 독립이지 완전한 제3자 독립은 아니며, 한 단계 분명한 개선으로만 해석해야 한다. 실트래픽 표적(6.12절)의 독립 재작성과 인간 작성 사례는 여전히 과제로 남는다.

6.14 실험 K: 노출된 약점 교정 — IP 신호 보정과 상태 추적

6.13절의 독립 holdout은 고정 규칙의 두 약점을 노출했다: (a) ip_distinct_accounts 단일 임계가 사무실 CGNAT·VPN 정상 사용자를 lock하는 공유 IP 오탐, (b) 무상태 per-event 채점이 다중이벤트 탈취의 정상처럼 보이는 첫 이벤트를 "miss"로 집계하는 문제. 이를 교정 규칙으로 전환해 같은 독립 holdout으로 재검증하였다(교정 규칙은 저자 설계이므로 규칙 자체엔 새 순환성이 있으나, 저자가 못 본 holdout 성능은 여전히 독립 증거다). rules3는 높은 공유 IP를 단독으로 lock하지 않고 다른 위험 신호(미등록 기기 또는 자격 실패)와 결합될 때만 lock하며, 실패 lock 임계를 3→5로 올렸다. rules_stateful는 rules3에 에피소드 이력(불가능 이동·geo 점프·재설정 후 새 기기)을 더해 시퀀스 신호를 반영한다.

(4) 교정 규칙(rules3·stateful)은 저자가 설계하여 그 규칙 자체엔 새 순환성이 있다 — 단 6.13의 규칙 비공개 독립 holdout으로 재검증했고, 합성·소규모라는 한계는 동일하다.

6.15 실험 L: 에이전트 아키텍처·지식표현 비교 (합성 멀티타겟, Docker 불필요)

§7.5에서 설계만 해둔 자율 에이전트 비교를, 실 CVE/Metasploit 격리가 아니라 합성 2자산 피벗 테스트베드 위에서 Docker 없이 수행하였다(루프백 전용, 코드 allowlist, 로컬 Ollama). 두 축을 비교한다 — (축1) 아키텍처: 단계가 고정된 파이프라인(A) vs 매 스텝 LLM이 행동을 고르는 ReAct(B); (축2) 지식표현(B 내부): 평면 리스트 vs networkx 듀얼그래프 (자산 그래프 + 작업 그래프를 공유 노드로 앵커). 목표는 host 'internal'의 crown jewel B 획득이며, 이는 host 'web'이 유출하는 자격증명을 'internal'로 피벗해야만 가능하다(그림 2).

범위 설정(정직한 고지): 이 실험의 연구 질문은 멀티호스트 피벗 추론·지식표현이지 SQLi payload 생성이 아니다. 따라서 ReAct 에이전트의 SQLi는 "능력"으로 추상화하였다(주입형 시도는 표준 작동 payload로 실행; 소형 모델은 비작동 payload에 고착하는 경향이 있어 1차 관문이 연구 질문을 가린다). 또한 소형 로컬 모델(qwen2.5-coder:14b, temp 0·seed 고정)이라 6반복이 완전히 동일 (결정적)했다 — 아래 수치는 통계 표본이 아니라 결정적 단일 궤적의 비교로 읽어야 한다(§6.9·6.11의 temp 0 한계와 동일).

(3) 격리는 루프백·코드 allowlist(≠OS 격리)이고 실 CVE·실 Metasploit·외부 벤치마크(AutoPenBench)는 미포함. 이들과 더 큰·다양한 모델은 VirtualBox VM + 내부 Docker 단계로 분리한다(§7.5). (4) "듀얼그래프 이득"은 이 피벗 과제에서 관측된 것으로, 더 많은 과제·모델에서의 재현은 후속 과제다.

6.16 실험 M: 외부 자율 하네스(Cochise) 격리 VM 실구동 — 셋업·호환성 소견·방어 함의

6.15절까지의 공격 에이전트는 모두 저자가 작성한 파이프라인이었다. 내적 타당성(순환성)을 더 낮추기 위해, 외부 제3자 자율 침투 하네스 Cochise(TU Wien, arXiv:2502.04227, TOSEM 2025; planner-executor 약 630 LOC)를 격리 환경에서 실제로 구동하였다. 원 논문의 테스트베드(GOAD, Active Directory)는 8GB VM에 과중하므로, Cochise의 시나리오만 교체해 6.10/6.12절과 동일한 합성 SQLi 웹 표적을 겨눴다(코드가 AD에 하드코딩돼 있지 않음을 정적 감사로 확인). "두뇌(LLM 추론)는 호스트, 손(shell)은 격리망 안" 원칙을 유지한다.

격리·토폴로지(실측): VirtualBox 7.2.22 VM(Ubuntu 24.04.5 · Docker 29.10.0) 안에 egress 차단 내부 네트워크(--internal)를 두고 표적(합성 SQLi 웹앱)을 그 안 컨테이너(172.18.0.2:8700)로 배치. 격리 실측: 컨테이너→외부 = Network unreachable(차단 확인), 호스트→컨테이너 = 도달. 공격자 박스는 VM 자신(localhost sshd + nmap·sqlmap·curl)이고 Cochise가 SSH로 접속해 명령을 실행한다. LLM은 호스트 Ollama를 루프백 전용 SSH 역터널로 연결(방화벽·LAN 노출 0). 전체 재현 절차·명령·함정은 저장소 research/AGENT_VIRTUALBOX_LAB_JOURNAL.md에 기록하였다.

측정 2 — 로컬 백엔드 비용/usage 텔레메트리 비호환

llama3.1:8b로 교체 후 Cochise의 planner 초기 계획 호출은 성공했으나, 비용 로깅 단계에서 크래시하였다 — Cochise 로거가 OpenAI식 usage 구조(prompt_tokens_details.cached_tokens, cost)를 가정하는데 Ollama/LiteLLM 응답은 이를 제공하지 않아 NoneType 역참조가 발생한다. 이는 외부 하네스를 로컬 백엔드로 구동할 때의 실제 통합 결함으로, 누락 필드를 방어적으로 처리하도록 로거를 한 곳 패치하여 해결하였다 (provenance 기록). 두 소견(측정 1·2)은 "호스티드 프런티어 모델을 전제로 만든 공격 하네스를 로컬로 내리면 그대로 돌지 않는다"는 점을 보여준다.

소견: "작은 로컬 모델이면 자율 공격 하네스를 쉽게 돌린다"는 가정은 성립하지 않았다 — 현재 로컬 코더계열 모델은 Ollama 네이티브 tool-calling 포맷을 안정적으로 지키지 못해 외부 자율 하네스(Cochise)와의 결합 자체가 끊기고, 비용/usage 텔레메트리도 OpenAI 전제라 그대로는 크래시한다. 이는 6.9/6.11/6.15절의 "모델 능력 티어가 결과를 좌우한다"를 공격 측에서 재확인하며, 위협 모델을 모델 능력 티어별로 세워야 한다는 본 연구의 하이브리드 티어 설계를 뒷받침한다.

★ 방어자를 위한 함의 (Defensive takeaways)

1. 격리가 1차 통제. 자율 에이전트는 받은 셸의 네트워크 도달 범위대로만 움직인다. egress 차단 세그먼트 + 범위를 1개 표적으로 못박는 것만으로 피해가 봉쇄됐다(실측). → 마이크로세그먼트·아웃바운드 기본 차단.
2. 허니토큰/디코이가 특히 유효. 열거형 에이전트는 정상 사용자가 안 가는 경로·자격증명을 건드린다 (6.10/6.12 미끼 접촉률 p_touch≈0.30 실측). → 단일 접촉을 고신뢰 알람으로.
3. 명확한 명령 시그니처는 규칙이 소형 LLM을 앞선다(6.12 은밀 SQLi 규칙 12/12 > LLM 1/6). → WAF·규칙이 여전히 1차, "AI 탐지 만능" 금물.
4. 탈취 자격증명 세션은 둘 다 못 잡는다(6.12 0/12). → 행위·맥락 기반(불가능 이동·신규 기기·접근 시퀀스)과 권한 최소화·단계적 재인증으로 보완(6.13/6.14).
5. 로컬 소형 모델의 하네스 호환성 취약은 양날의 검. 단기적으로 "로컬 only 자율 공격" 신뢰도는 낮지만(측정 1·2), 프런티어·호스티드 모델은 다르므로 위협 모델을 능력 티어별로.
6. 공격 도구 자체가 위험. Cochise는 known_hosts=None+LLM 입력 미정화로 프롬프트 인젝션→RCE 소지, AutoPenBench는 eval()·실 CVE 익스플로잇 포함. → 격리에서만, 감사 후 실행(본 랩은 egress 0 + CVE 미실행으로 준수).
상태·한계: 본 절은 격리 셋업·호환성 측정(측정 1·2)·20분 실구동 트래젝터리(측정 3)까지 완료하였다. 한계: 표적 합성 1종(AD 아님), 공격자 박스=VM 자신 (실 다중호스트 피벗 아님), 단일 소형 로컬 모델, 통계 아님(스모크 1회). 순환성은 공격 하네스가 외부 제3자라는 점에서 완화이지 제거가 아니며, 표적은 여전히 저자 작성이다. tool-calling 때문에 6.15절과 모델이 달라질 수 있음을 명시한다.

6.16b 실험 M-2: 두 번째 외부 하네스(AutoPenBench) 로컬 구동 — 공격자·평가자 이중 실패

§6.16의 Cochise에 이어, 두 번째 외부 제3자 자율 침투 하네스 AutoPenBench (arXiv:2410.03225, MIT; 33과제·마일스톤 평가)를 같은 격리 VirtualBox VM에서 로컬 Ollama로 구동하였다 — 외적 타당성을 한 하네스에 의존하지 않기 위함이다. 표적은 AutoPenBench 자체의 합성 취약 컨테이너 (in-vitro/access_control/0: 호스트 발견→student 로그인→권한상승→/root/flag)이며 실 CVE가 아니고, 모든 트래픽은 VM 내부 격리 Docker 네트워크 안에 머문다.

로컬 구동을 막은 두 블로커(실측)와 우회. 원 하네스는 (1) 에이전트 행동을 instructor 구조화출력(Union 응답모델)으로 받는데 소형 로컬 모델은 인스턴스 대신 JSON 스키마를 반환해 파싱이 깨지고(§6.16 측정 1의 tool-calling 실패와 동일 계열), (2) 고정 커밋의 PentestDriver에는 예제가 호출하는 step() 메서드가 아예 없었다. 두 가지를 모두 우회하는 러너를 작성하였다 — 평문 {"tool","args"} JSON 액션을 직접 파싱해 pydantic 도구 인스턴스를 만들고, 누락된 step() 디스패치를 재구현하였다(ExecuteBash·SSHConnect· WriteFile·FinalAnswer). LLM 없이 디스패치를 검증하는 오프라인 모드로 실제 컨테이너 상호작용(nmap·SSH 터널)을 먼저 확인한 뒤, llama3.1:8b로 실궤적을 수집하였다.

측정 1 — 공격자(소형 로컬모델) 실패: §6.16을 세 번째 하네스에서 재현

llama3.1:8b는 매 스텝 파싱 가능한 JSON 액션을 생성해 우회 자체는 성립했으나(= instructor 없이 로컬 구동 가능), 관측 기반 그라운드 트루스로 보면 공격은 실패했다 — 실제로 달성한 것은 nmap 호스트 발견 한 가지뿐이고, 포트 스캔·크리덴셜 탐색 없이 찍은 자격증명(student/student)으로만 반복 시도해 타깃 셸·루트·플래그를 전혀 얻지 못했다(SSH 인증 실패 반복, ssh_connect를 bash 명령으로 오타, 자격증명을 파일에 쓰는 등 도구 오용). 이는 §6.16(Cochise)의 "소형 로컬 모델은 트래픽만 만들고 목표는 실패"를 세 번째 독립 하네스에서 재현한 것이다.

(나) 그 사실을 정량 측정·보고한 것이 학문적 기여다: 다수의 자율공격 벤치마크가 LLM 판정자에 의존하는데, 그 신뢰성 한계를 수치(86%/80%)로 드러내 "벤치마크 점수는 어떤 판정자로 쟀는지와 함께 보고해야 한다"는 실무 지침을 주기 때문이다. 즉 "판정자가 부정확하다"(부정적 사실)와 "그 사실을 밝힌 것이 유용하다"(연구 가치)는 모순이 아니라 서로 다른 차원의 진술이다.

6.16c 실험 M-3: 세 번째 외부 하네스(PentAGI) 로컬 구동 — tool-calling 성립과 실제 Flow 실행(ground truth)

Cochise(§6.16)·AutoPenBench(§6.16b)에 이어 세 번째 외부 하네스 PentAGI(prebuilt 멀티컨테이너, 네이티브 Ollama provider·역할별 모델)를 같은 격리 VM에서 로컬 Ollama로 구동하였다. 하드닝(.env: DOCKER_INSIDE=false · UPDATE_CHECK_INTERVAL=0 · DOCKER_NET_ADMIN=false, Ollama 로컬 지향)을 적용하고 pentagi+pgvector를 기동하였다. VM 내 컨테이너가 호스트 Ollama에 직접 도달해(10.0.2.2:11500) 별도 프록시가 필요 없었다.

tool-calling 선검증(ctester) 결과 — 229개 역할×테스트 중 215 PASS / 14 FAIL: PentAGI 내장 ctester를 Ollama provider로 실행해 13개 역할(primary_agent·assistant·generator·pentester 등)을 여러 함수호출 테스트 범주(Basic Echo Function·Math Calculation·Function Argument/Response Memory·Tool Call Memory·구조화 JSON 출력·침투테스트 방법론 등)에 걸쳐 검증하였다. llama3.1:8b는 215건을 통과([PASS])했고, 실패는 14건이었다. 핵심은 14건의 실패가 전부 동일한 단일 테스트("파일을 읽은 뒤 unified diff로 편집하라", read-before-edit)였다는 점이다 — 모델이 첫 호출로 read_file 대신 edit_file을 선택한 계획·순서(planning-order)의 결함이지, 구조화 tool_calls를 생성하는 tool-calling 능력 자체의 실패가 아니다(에코·수학·메모리·JSON 구조화 출력은 모든 역할에서 통과). 따라서 소형 로컬 모델로도 PentAGI 수준의 tool-calling이 성립하되, 다단계 작업의 행동 순서에는 약점이 있음을 함께 측정하였다. 이는 §6.16(Cochise)에서 coder 계열(qwen2.5-coder·deepseek-coder)이 구조화 tool_calls 자체를 생성하지 못한 것과 대조되며, "tool-calling 성립 여부는 모델 선택의 문제"라는 소견을 세 번째 하네스에서 재확인한다. (로컬 추론이 느려 일부 역할 테스트가 ~1분 50초 소요; 수치는 역할·범주를 폭넓게 커버한 실행 기준이다.)

"도구를 호출할 수 있다"와 "자율적으로 공격을 완수한다"는 별개이며, 그 차이를 모델의 자기보고가 아니라 표적측 ground truth가 드러낸다(본 논문의 일관된 명제).
한계·안전: (1) 단일 표적·단일 모델·1회 실행(temp 기본)이라 통계가 아니라 사례 관측이다 — 더 강한 모델/다중 실행은 결과가 다를 수 있다(§6.11·§6.19의 모델 의존성). (2) 샌드박스 공격 셸은 egress 0 격리망에 고정했으나, PentAGI의 보조 browser/search 도구는 별도 scraper 서비스(인터넷 접근)로 동작해 에이전트가 example.com을 조회할 수 있었다 — 공격 셸은 격리됐지만 보조 도구 경로는 완전 격리가 아니므로, 더 엄격한 재현에서는 scraper까지 차단해야 한다. 6.16d 실험 M-4: 제약된 자율 하네스에서 소형 로컬 모델의 자율 공격 성공 — 그리고 그에 대한 방어

★ 금융권 위협과의 직접 연결: 최근 금융권의 지배적 API 위협이 바로 이 시그니처 없는 업무로직 공격(BOLA·파라미터 조작 — 시그니처 도구와 rate limit이 놓치는 유형; Thales/Imperva 2025, 금융이 API 공격 1위 표적)이다. §6.16e에서는 한발 더 나아가 실제로 성공한 자율 공격(소형 모델이 BOLA로 타 고객 계정을 읽고 mass assignment로 관리자 권한을 탈취한 세션)까지 인가-맥락 LLM이 탐지했고 시그니처는 놓쳤다 (정상 오탐 0). 즉 시그니처·임계값 규칙이 구조적으로 실패하는 이 공격군에서 LLM(맥락) 탐지가 실질적 방어가치를 가짐을, 작동하는 자율 공격에서까지 확인하였다 — 단 인가 맥락 제공·모델 선택·규칙+LLM 앙상블이 전제다.

7. 논의 (Discussion)

7.1 AI의 추가 가치에 대한 해석 주의

항상 안전한 구현과 동기 AI 조건이 동일한 보안 결과를 보이더라도, AI의 필요성이 입증되는 것은 아니다. 동기 AI 방어에서 Qwen은 첫 번째 정상 요청을 분석한 뒤 parameterize를 선택하였다. 즉 공격을 식별한 뒤 대응한 것이 아니라, 첫 요청부터 안전한 구현으로 전환한 결과다. SQL 바인딩을 처음부터 적용하는 비교군은 모델 호출을 요구하지 않는다.

7.2 고정 규칙의 한계와 의도된 반례

고정 규칙의 정상 계정 차단(team--blue의 HTTP 403)과 공격 누락(SQL 주석 변형 3건)은 의도적으로 작성한 반례다. 이 수치로 상용 WAF나 다른 규칙 기반 시스템보다 AI가 우월하다고 주장할 수 없다.

7.3 타당성 위협

주요 타당성 위협:

(1) 내적 타당성: 사례 작성자와 구현 작성자가 같고, 규칙에 맞춰 사례를 구성하였다 — 단 ATO 탐지기는 6.13절의 규칙 비공개 독립 holdout으로 재검증하여 이 위협을 부분적으로 완화하였다(저자가 AI 에이전트라는 한계는 잔존).
(2) 외적 타당성: 표본 소규모 (10사례×5조건×3반복), SQL 인증만 평가, XSS·IDOR·행동 적응 미포함.
(3) 모델 의존성: 단일 모델·프롬프트·seed 사용, GPU 점유율 별도 측정 없음.

7.4 향후 연구

(1) 독립 작성한 보류 사례와 정상 업무 트래픽으로 외적 타당성 확보 — ATO 탐지기는 6.13절에서 규칙 비공개 독립 holdout(별도 AI 에이전트 작성)으로 재검증 완료(정확도 유지), 정상 업무 실트래픽과 인간 제3자·실트래픽 표적의 독립 재작성은 미수행
(2) 여러 모델 계열로 공격자·방어자를 교차하는 모델 의존성 평가 — 6.9절의 사다리는 공격자·방어자가 동일 모델 계열이라는 한계를 남겼고, DeepSeek-Coder와 Qwen을 교차하는 후속 실험을 6.11절에서 완료(2계열 한정, 추가 계열은 미수행)
(3) 도착률 통제를 통한 비동기 노출 구간 정밀 측정 — 6.5·6.7절에서 결정적 등간격 도착으로 수행, 포아송 도착과 동기 조건의 지연 비교는 미수행
(4) XSS·IDOR로 실험 범위 확장 — 미수행. 행동 적응은 6.6~6.9절(적응형 공격자, 능력 사다리)에서 수행

(6) 자율 공격 에이전트 실험: 현재 공격자는 로그인 시도의 속성만 고르는 선택기이며 실제 코드 실행이나 탐색 행동을 하지 않는다. 격리된 Docker 환경에 자체 제작한 취약 표적과 범위가 제한된 최소 기능 에이전트(HTTP 요청만 가능)를 두어, 미끼 접촉률을 실측하고 자율 에이전트 대비 방어 효과를 재검증할 계획이다. 범용 침투 프레임워크(예: ARTEX)는 실제 악용 의혹이 보도된 바 있어 도입하지 않는다.
(7) 가상화 기반 격리 환경에서 운영 성능 평가

7.5 자율 공격 에이전트 도입 계획 (합성 비교 §6.15 완료, 실 CVE는 Docker 단계)

6.9~6.10절의 공격자는 로그인 시도의 속성만 고르는 선택기이며 실제 명령 실행이나 탐색 행동을 하지 않는다. 이 한계를 넘기 위해 공개·재현 가능한 자율 침투 에이전트 도구의 도입을 검토하였다. 본 환경(Windows 11 Home)은 Docker가 설치되지 않아 실 CVE/Metasploit 경로는 시작하지 못했다. 다만 아키텍처·지식표현 비교 자체는 Docker 없이 합성 멀티타겟 테스트베드에서 수행하여 6.15절에 보고하였다(ReAct vs 고정, networkx 듀얼그래프 vs 평면). 실 CVE·실 Metasploit·AutoPenBench와 더 큰 모델은 VirtualBox VM + 내부 Docker 단계로 남는다.

Cochise 논문은 스스로 "최첨단 공격 도구가 아니라 모델·에이전트 구조·침투 흔적을 비교하기 위한 재사용 가능한 실험 인프라"라고 명시하며, 신뢰된 점프 호스트에서 SSH로 격리된 테스트베드만 공격하도록 설계되어 있다. AutoPenBench는 완전 자율 에이전트 21%, 사람 보조 에이전트 64%의 공개 기준 성공률을 제공해 비교 기준점이 된다. AutoPenBench의 "EMNLP 2025 Industry Track 게재" 주장은 arXiv 등재 정보로 확인되지 않았다(미확인으로 표기한다).

자율성과 안전성을 혼동하지 않는다: Cochise의 익스큐터는 매 단계 LLM이 명령을 자유롭게 생성하므로, 자율성 수준 자체는 ARTEX와 다르지 않거나 더 즉흥적이다. Cochise를 선택한 근거는 자율성이 낮다는 것이 아니라 (1) 공격 범위가 설계상 격리 테스트베드로 한정됨 (2) 630줄로 코드 감사가 가능함 (3) 악용 보고가 없음(증거 없음일 뿐 안전 증명은 아님)이다. 실제로 Cochise 저장소의 미해결 이슈(#13, 2026-08-04)는 SSH 호스트 키 검증 비활성화와 LLM 응답 미정제로 인한 프롬프트 인젝션 기반 2차 명령 실행 가능성을 제기한다(코드로 직접 검증하지 못함). 안전은 에이전트의 자율성 수준이 아니라 연구자가 구성하는 네트워크 격리에서 나온다는 것이 이 검토의 결론이며, 어떤 에이전트를 쓰든 격리된 네트워크(외부 인터넷 차단)와 저희가 통제하는 표적이라는 전제는 필수로 둔다.

두 번째 에이전트 구조: 고정 파이프라인 (구조 비교 변수)

Cochise(매 단계 LLM이 자유롭게 명령 선택)와 비교할 대조군으로, 단계는 고정하고 LLM은 제한된 선택지 안에서만 결정하는 두 번째 에이전트 구조를 설계하였다: (1) 정찰 — Nmap 실행, LLM 미개입 (2) 스캐닝 — 서비스 버전별 후보 취약점/모듈 중 LLM이 선택 (3) 익스플로잇 — Metasploit(msfrpc)으로 선택된 모듈 실행, LLM은 모듈 옵션만 채움 (4) 보고 — JSON 로그, LLM 미개입. Metasploit 모듈은 AutoPenBench 과제에 맞춘 화이트리스트로 제한하고, Nmap 스캔 대상 IP도 코드에서 격리 네트워크 내부로 고정한다. 지표에 "정찰·스캐닝·익스플로잇 중 어느 단계에서 막혔는가"를 추가해 방어가 작동하는 시점을 구조별로 비교한다.

공격자·방어자 모델 티어 (하이브리드 — 로컬 + API)

현재 실험은 로컬 양자화 모델(Q4)만 사용하는데, 이는 호스팅 프런티어 모델을 쓰는 실제 공격자보다 약해 위협을 과소평가할 수 있다. 실제로 ARTEX는 OpenAI 호환 엔드포인트(예: DeepSeek API)와 기본 모델 claude-opus-4-8을 쓰며, 참조 논문(2611.07611)도 Opus 4.8을 에이전트로 사용하였다. 반대로 API만 쓰면 호스팅 모델의 버전 변경·폐기로 재현성이 약해진다. 따라서 로컬 + API를 병행하는 하이브리드로 간다.

(4) 프롬프트에는 합성 데이터만 넣고 개인정보는 포함하지 않는다. (5) 호스팅 모델은 호출 시각·버전을 명시하고 로컬 결과와 나란히 보고한다. 진행 순서: 로컬 교차 모델 마무리 → Docker 격리 → DeepSeek API 공격자 → 결과 보고 → (비용 승인 후) Claude 공격자.

검토한 구조 개선 제안: "Cochise에 이중 그래프 추가"(기각·정정)

ARTEX의 이중 그래프 구조(태스크 진행을 보는 탐색 그래프, 발견된 자산을 보는 공유 자산 그래프, 둘을 앵커로 연결)를 Cochise의 "단일 트리 구조"에 통합하면 독창적 기여가 된다는 제안을 검토하였다. 전제를 소스코드로 확인한 결과 부정확하였다: Cochise는 이미 단일 구조가 아니다. 논문(arXiv:2605.11671 §3.2)과 저장소 소스(planner.py)를 직접 읽은 결과, 플래너는 장기 상태를 PTT(Pentest-Task-Tree, Deng 외 2026의 pentestGPT에서 가져온 마크다운 트리, 기본 설정일 뿐 하네스가 고정 의존하지 않음)로 유지하면서, 별도의 Knowledge 컴포넌트 (knowledge.py)가 탈취 계정·발견 서비스·공격 단서를 독립적으로 추적한다. 즉 "작업 계획"과 "발견 자산"을 이미 분리해서 관리하고 있다. PentestTaskTree라는 클래스는 존재하지 않으며, 실제 클래스명은 Planner와 Knowledge이다.

정정된 기여 제안: "단일 구조에 이중 그래프를 처음 도입한다"는 주장은 사실과 다르므로 쓰지 않는다. 대신 "Cochise의 비정형 Knowledge 컴포넌트(자격증명·엔티티 나열 수준)를 ARTEX 방식의 정식 그래프(networkx, 탐색 그래프와 자산 그래프를 앵커로 연결)로 교체하여, 멀티타겟 환경에서 에이전트 성능이 어떻게 달라지는지 비교한다"로 기여 범위를 좁힌다. 이 변경은 Docker 도입 이후 Knowledge 컴포넌트 교체 실험으로 다룬다. 성능 향상 수치(예: "XX% 향상")는 측정 전에는 논문에 쓰지 않는다 — 실측 없이 숫자를 제시하는 것은 이 연구 전반의 "실측값만 보고한다"는 원칙에 위배된다.

8. 결론 (Conclusion)

본 연구는 "AI 적응형 공격에 대한 AI 방어가 가능한가, 효과가 얼마나 되는가, 어떻게 대비해야 하는가"를 로컬·합성 환경에서 세 축(SQL 정책 시점, 계정 탈취 능력 사다리, 다중 모델 교차)으로 실측하였다.

실험으로 뒷받침되는 발견: (1) 동기 AI 방어는 공격 성공 0건을 달성했으나 응답 지연 (판단→응답 p95 2,031ms)이 따랐고, 비동기 AI 방어는 속도를 유지하는 대신 패치 전 노출 구간이 요청 도착률×추론시간에 비례해 생겼다. (2) 능력 사다리에서 비밀번호만 아는 공격자는 거의 모두 막혔으나, 탈취된 기기·세션을 가진 공격자(L3)는 여섯 방어 중 다섯이 80% 이상 뚫렸다 — 로그인 시점 정보만으로는 구분이 불가능한 구조적 한계다. (3) LLM 방어는 규칙보다 정상 사용자 마찰을 크게 줄였으나 중간 난이도(L2) 공격을 더 통과시키는 트레이드오프를 보였다. (4) 교차 모델(DeepSeek↔Qwen, n=12)에서 L3를 막은 유일한 설정은 DeepSeek 방어자+llm_escalate(0/12)였고 Qwen 방어자는 같은 방식으로도 뚫렸다(12/12) — 효과는 방어 방식이 아니라 방어자 모델이 결정했으며, 더 강한 판단에는 2~9배 지연 비용이 따랐다. (5) 금융 API 업무로직 공격(BOLA·mass assignment)에서는 시그니처 규칙이 0/12로 완전히 실패한 반면 인가-맥락 규칙과 LLM은 각각 12/12·6/6로 탐지해, 탐지기 선택 기준이 "공격이 시그니처로 정의되는가(→규칙) vs 인가 맥락으로 정의되는가(→맥락 규칙·LLM)"임을 보였다(§6.17). 나아가 제3자 blind 독립 holdout(§6.19)에서 손수 만든 규칙은 과적합으로 하락(맥락규칙 12/12→13/18)한 반면 LLM(맥락)은 17/18로 가장 잘 일반화해, "AI의 일반화 가치"가 저자 데이터가 아닌 독립 데이터에서 확인됐다(단 오탐 2/12의 정밀도 비용 동반 → 규칙+LLM 앙상블 권고). 이 LLM 우위는 모델 의존적이어서 같은 holdout에서 llama3.1:8b는 15/18로 우위였으나 deepseek-coder-v2:16b는 6/18로 규칙보다도 낮았다(§6.19 교차모델) — "어떤 LLM이냐"가 효과를 결정한다.

즉 "AI 방어가 효과적인가"의 답은 단정형이 아니라 "어떤 모델이, 어떤 공격 난이도에, 어떤 지연·마찰 비용으로 작동하는가"라는 조건부이다. 어떤 방어도 막지 못한 L3 구간에 대해 기만(shadow) 방어와 자율 공격 에이전트 검증을 위해 외부 하네스 Cochise를 격리된 VirtualBox VM에서 실제로 구동하는 단계에 진입하였고(§6.16; 로컬 모델 tool-calling·비용 로깅 호환성 소견 확보), Cochise는 20분 실구동까지 완료하였고(§6.16 측정 3: 실제 공격 트래픽 332건을 생성했으나 인증 우회·크라운주얼 미달성, 성공을 자기보고하는 환각 관측), 두 번째 외부 하네스 AutoPenBench도 로컬로 구동하여(§6.16b) 같은 공격자 실패를 재현하였고, 나아가 약한 LLM 평가자가 성공을 과대보고(실패를 성공으로 잘못 판정)(command 거짓양성 86%·stage 80%)함을 결정적 그라운드 트루스로 드러내 "자기보고를 믿지 말라"는 명제를 평가자에게까지 확장하였다.

★ 그러나 이 "자율 공격 실패"는 모델의 무능이 아니라 개방형 하네스·실행 불안정의 산물이었다(§6.16d·e). 행동 공간을 실제 공격 동작으로 제약하고 실행 오류를 바로잡자, 동일한 소형 로컬 모델(llama3.1:8b)이 행동과 페이로드를 스스로 작성하며 자율적으로 공격에 성공했다 — SQL 주입 ~73%(11/15), 금융 API 업무로직(BOLA+권한상승) 10/10, 모두 표적측 ground truth로 확정. 더 중요한 것은 이렇게 성공한 자율 공격에 대한 방어가 공격의 정의에 따라 정확히 갈렸다는 점이다: 시그니처가 있는 SQLi는 규칙이 잡고 소형 LLM이 놓쳤으나, 시그니처가 없는 금융 API 업무로직 공격은 시그니처가 놓치고 인가-맥락 LLM이 포착했다(정상 오탐 0). 이는 §6.12·§6.17의 "공격이 시그니처로 정의되면 규칙, 인가 맥락으로 정의되면 LLM"이라는 결론이 실제로 성공한 자율 AI 공격 두 종에 대해서도 성립함을 뜻하며, 특히 최근 금융권의 지배적 위협인 시그니처 없는 API 공격(BOLA 등)에 대해 LLM(맥락) 기반 탐지가 실질적 방어가치를 가짐을 — 작동하는 자율 공격에서까지 — 시사한다(전제: 인가 맥락 제공, 모델 선택, 규칙+LLM 앙상블).

현재 근거는 소규모 합성 테스트베드의 기능·기전 검증이다. 사례 대부분은 개발자가 작성했고 (ATO 탐지기는 6.13절에서 규칙 비공개 독립 holdout으로 재검증하여 순환성 우려를 완화했으나, 저자가 AI 에이전트라는 한계가 남는다), 능력 사다리는 동일 모델 계열이며, 교차 모델은 2계열·셀당 n=12 규모이고 동일 설정 2회 실행 중 3셀이 불일치했다. 따라서 본 연구는 AI 방어의 일반적 우월성을 주장하지 않으며, 독립 사례·실트래픽·자율 에이전트 환경에서의 추가 검증이 필요하다. 또한 LLM 판단 지연(§6.3의 동기 p95 2,031ms, §6.11의 2~9배 지연)은 향후 호스티드 상용 결정모델(예: Jev)에 의존하지 않고 로컬 전제를 지키는 방식 — 규칙→LLM 캐스케이드(명확 케이스는 규칙이 즉시 처리해 LLM 호출 수 감소), LLM 판사의 소형 분류기 증류, 또는 오픈 타입드-결정 모델(JPT-4B) — 으로 속도를 개선할 계획이다. 사고 대비에 관한 7장의 권고는 실험이 아니라 문헌과 구조적 관찰에 근거한 것임을 다시 밝힌다.
